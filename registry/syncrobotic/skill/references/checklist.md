# Check after every UI change

Run through each line for the files you changed, fix what fails, then report.

1. Every value is a token: no hex, no `px` in class names, no `duration-150`, no `ease-in-out`, no font size or weight off the scale.
2. Every duration class has `ease-(--ease-standard)` beside it. Leaving uses the exit animations (`animate-disappear`, sheet-out, collapse), which carry `--ease-exit`.
3. Interactive things are at least 44 px on touch; 36 (`--h-sm`) with a mouse only. They use height tokens, never fixed sizes, so `data-density` (glove, compact) works.
4. Colour appears only on what needs someone (a level past its threshold shows the status glyph and word, never only an amber number); calm states are grey (offline too); blue only for a bounded process being waited on (the running work's bar or cell is blue, its state word stays grey); status is a shape and a word, colour only when it is abnormal; no solid red except the stop; disabled text stays readable; battery warns below 15 % and never turns danger.
5. Every chart with axes (line, area, bar, heatmap) has a table view; chart colour is only on the series that matters (`--chart-1`), the rest graphite, three series and Other at most; sparklines, rings and status strips write their numbers in words instead; field edges use `--input`; nothing focusable removes its focus ring (`outline-none` only with a visible replacement).
6. Each registry part is used as its `.md` twin says:
   - Field around controls, InputGroup for icons in inputs, Meter for levels, CountBadge for counts, Alarm for what needs action, NumberField for numbers.
   - Code for a path or key in a sentence (size never set, a CopyButton beside it); Collapsible for one "More" region (never a raw `<details>`).
   - Facets for a facet column beside a list (FacetsDrawer on phones, same value; never a hand-made column or sheet of checkboxes); BarList for a short ranked list of counts (one series in `--chart-1`, the value in each row's text; never Meters in rows or a chart card).
   - Thumbnail for a small picture in a row or card (a restricted one is `restricted` with a `reason`: nothing is fetched); ImageGrid's `onOpen` with your own dialog calling the grid ref's `restoreFocus()` in its `onCloseAutoFocus`.
   - StreamingText for a model's streamed answer (no blinking caret, status said once, read in sentences); GroundedTextBody beside an annotated-image the screen already shows (wired with `groundedImageProps`, never a second GroundedText).
   - ViewportOverlay and ViewportPanel for anything over a map, point cloud, 3D view or camera (16 px in, Float or the scrim, never `bg-background` or a corner of your own); ChartViewSwitch for a Chart / Table or Map / List switch in a card header (`--h-sm`, never a hand-built SegmentedControl); ResponsiveTable for rows phones see too (each column with its `phone` place; never a hidden Table beside a hand-written phone list).
7. Enter and exit both animate; loops only while waiting (Spinner, skeleton, caret); reduced motion is respected.
8. Icons come from the icon set, one meaning each; icon-only buttons have an aria-label; images have alt; headings are in order (no skipped level: CardTitle, AccordionTrigger, PageHeader and SectionHeader take `as`, CardDataHeader `titleAs`, so a card or accordion right under the h1 is an h2; a status page inside top-bar-shell, which has no page title, takes `as="h1"`, and its way out is a link: `primary={{ label, href }}` with `linkAs`); focus is visible.
9. Empty, loading and error states exist for every list, table and page you touched. Every empty state is `EmptyState` at its host's size (`panel` on a card, `size="inline"` in a table, list or small panel, `variant="overlay"` over a canvas), never a hand-made icon and paragraph; skeleton bones that stand in for a control take its height token (`h-(--h-md)`, `h-(--h-sm)`), never `h-10`.
10. A fetched region is a `DataState` (from `dataStateOf`), its counts from the server's `total`; an action the viewer lacks is a `PermissionGate` decided by a permission string, disabled ones with a `reason`; a server-paged list keeps its query in the URL with `useListQuery`. A limit that may be unlimited is a `QuotaField` (`null`, never 0), an entitlement that may grow (all modules, including future ones) an `AllOrSomeField` (`null`, never every box ticked), and permission scopes a `ScopePicker` bounded by the viewer's `allowedScopes`.
11. Light and dark both read correctly (the theme does this if you used tokens).
12. A full-screen workspace (history, main, controls) is `action-rail-shell` with `leading` and `panel`, not a hand-built shell or `top-bar-shell`; top-bar items that may not fit go in `headerItems`, which fold into ⋯ instead of wrapping; below 1280 px the leading column is reached from a top-bar button that opens a Sheet.
13. One part per repeated look: an icon on a tile is `IconTile`, a robot's ID or initials on a tile is a square `Avatar`; a ⋯ menu is `DropdownMenuMoreTrigger` (ghost; "More actions for {name}" in a row, "More actions" in a toolbar, "View options" for a view menu), in a table inside `TableActionsCell`; a section title is a `SectionHeader`: `page` (20 px bold) between the page's cards, `surface` (14 px medium, never bold) inside a card or a panel's head row (a data card's is `CardDataHeader`), never a hand-sized title; a toggle group with `type="single"` holds a tool or a mode, never a view or a time window (that is a `SegmentedControl`).
14. Inside a rounded surface an indicator is an inset pill in its own gutter and a selected card a 2 px ring, never a straight strip or a one-sided border against the rounded edge; a status word is not repeated beside the button that already says it.
15. Live data goes stale: a camera, chart, joint state, robot model, attitude, gauge, point cloud or diagnostics panel fed from a robot keeps its default `staleAfterMs` (or one near three missed messages of its topic) and gets the message's stamp; `staleAfterMs={null}` only for data that is not live (a saved map, a recording, a model on show). A device's reported values carry a `FreshnessStamp`; an order not yet confirmed is a `DesiredState`, a device's own claims an `EvidencePanel`; times go through `relative-time`.
16. Numbers are tabular; a count is in full with grouping (`formatCount`) in tables, headers and detail, and abbreviated (`formatCount(n, { compact: true })`) only on a tab's count, a chart's ticks or a compact chip, with the full number one step away; never a hand-made "k". Every other number goes through `formatNumber`; no `toLocaleString()`.
17. A state is an `InlineStatus` (in a row, a cell, or `PageHeader`'s `status`, one per header); a fixed attribute is a neutral `Badge`; a count is a `CountBadge`. Never a state in a `Badge` or a `MetaPill` (neither has a status tone).
18. A conversation with a model uses the conversation parts, never a hand-made chat (start from `agent-chat`; `AgentChatContent` inside your own frame):
   - Each turn a `Message` (the role word says who spoke, never a bubble colour; a person's turn `align="end"`), as direct children of a `MessageScroller` with a height (`min-h-0 flex-1` in a column ending with the composer; never scrolled by hand), and a `PromptComposer` at the foot with `streaming` and `onStop` while an answer arrives (no fixed positioning).
   - A streamed answer is `StreamingText` (`format="markdown"` for Markdown, `markdownProps` a module constant); sources in `Citations` around it with `markdownProps={{ cite: citationMarker }}` and `CitationSources` under it, its heading level set from where it sits. A whole answer is `Markdown` alone.
   - Under each settled answer: `MessageActions` in `actions` (`quiet={false}` on the latest), `MessageMeta` in `footer`. Tool calls are a `Trace` in a tool turn. A new conversation is the scroller's `empty`: an EmptyState with suggested prompts.
   - An agent that would move a robot proposes; a person approves (`agent-approval`).
